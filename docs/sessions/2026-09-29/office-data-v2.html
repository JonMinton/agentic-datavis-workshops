TidyTuesday for 2020-03-17 covers the US version of The Office (NBC, 2005–2013). The week itself ships one table, IMDb ratings per episode, and points to the schrute R package for the full dialogue. Both are described here.

TipReproducing this page

Runs from two CSVs cached in data/. The ratings CSV is committed in this repository. The transcripts CSV holds the show’s full dialogue, so it is not committed; the second block below rebuilds it locally. To refresh from source:

A first figure: ratings by season and episode

The first spec asked for a heatmap: season as rows, episode number as columns, and IMDb rating as fill. Everything else is left at ggplot2’s defaults.

# sessions/2026-09-29/specs/01-office-heatmap.yml

  x: episode
  y: season
  fill: imdb_rating

Code 
ggplot(ratings, aes(x = episode, y = season, fill = imdb_rating)) +
  geom_tile() +
  theme_minimal(base_size = 13)

Looking at the render shows three defaults that nobody decided on:

  • season is stored as a number, so ggplot2 treats it as continuous. The axis shows breaks at 2.5, 5.0 and 7.5, which are seasons that don’t exist.
  • The default continuous y scale puts season 1 at the bottom and season 9 at the top.
  • The default fill gradient runs from dark to light blue, which leaves little contrast across the 6.7–9.7 range.

The ragged right edge shows how many episodes each season had. Season 1 is the shortest, with 6 episodes.

A second figure: ratings over air date

The second spec puts each episode at its air date, colours it by season, and adds a smoother. Two decisions were made before compiling:

  • Season as a category. season is stored as a number, so the spec maps factor(season) to colour, which gives one hue per season instead of a gradient. Shape was dropped: ggplot2’s default shape palette has only six shapes, so seasons 7–9 would have gone missing.
  • One smoother per season. Colour is mapped for the whole plot, so the smooth layer inherits it and fits a separate curve to each season.
# sessions/2026-09-29/specs/02-office-airdate.yml
data: tt-2020-03-17-office_ratings
mapping:
  x: air_date
  y: imdb_rating
  colour: factor(season)
layers:
  - geom: point
  - geom: smooth
Code 
ggplot(ratings, aes(x = air_date, y = imdb_rating, colour = factor(season))) +
  geom_point() +
  geom_smooth() +
  theme_minimal(base_size = 13)

Looking at the render:

  • The smoother defaults to loess, which is very wiggly when seasons are this short (a median of 23 episodes). Season 1’s 6 episodes give a spike with no confidence ribbon, and R prints a warning while fitting it.
  • Season 4’s ribbon balloons across a gap in its air dates. Loess is drawing a curve through months with no episodes.
  • Several seasons end on a rise, most sharply the finale at 9.7. A flexible smoother bends towards the last point or two, so these end-of-season spikes need checking against the raw points before reading anything into them.
  • The legend title is the code factor(season), and the axis titles are raw variable names, because the spec has no labs block yet.

Revisions to the first two figures

The facilitator reviewed what the renders had revealed and made these decisions:

  • Season is a category, not a cardinal number. Season 3 isn’t “three times” season 1.
  • Season 1 goes at the top, so the heatmap reads like a table.
  • The fill uses viridis for more contrast across the ratings.
  • Per-season smoothers become straight lines (method: lm).
  • A second version shows one smoother for the whole series.
  • Every figure gets proper labels.

Code 
ggplot(ratings, aes(x = air_date, y = imdb_rating, colour = factor(season))) +
  geom_point() +
  geom_smooth(method = "lm") +
  labs(title = "Ratings over the run, with a linear trend per season",
       x = "Original air date", y = "IMDb rating", colour = "Season") +
  theme_minimal(base_size = 13)

geom_smooth(method = "lm") runs a regression that doesn’t appear anywhere in the code. For each season, ggplot2 fits lm(imdb_rating ~ air_date) to that season’s episodes and draws the fitted line with a 95% confidence band. The straight lines are far steadier than the loess curves of the first version. Season 4’s line now crosses its gap in air dates without bending. That gap is still worth knowing about: a line drawn through months with no episodes claims nothing about them.

A 3D view, with the models made explicit

Code 
# Within-season lines: season as a category, with its own intercept and slope.
# This parameterisation gives each season's intercept and slope directly.
m_lines <- lm(imdb_rating ~ 0 + factor(season) + factor(season):episode, data = ratings)

# Across-season planes: season as a cardinal number.
m_plane <- lm(imdb_rating ~ episode + season, data = ratings)   # flat plane
m_twist <- lm(imdb_rating ~ episode * season, data = ratings)   # twisted plane

r2 <- \(m) sprintf("%.2f", summary(m)$r.squared)

# Comparable R² for the within-season model: refit it with an intercept (same fitted
# values, same residuals) so R² is measured against the mean rating, not against zero.
r2_lines <- summary(lm(imdb_rating ~ factor(season) * episode, data = ratings))$r.squared

Rating is elevation, episode is x and season is y. Use the buttons to add one of three linear models. The table alongside updates to show the model behind the surface, its lm() call, and its coefficients. Drag to rotate the view, and scroll to zoom.

Seen from straight above, this is the heatmap again, with rating as height instead of colour.

The buttons offer two kinds of model:

  • Within-season lines treat season as a category, as the facilitator decided. Each season gets its own intercept and slope, so this is the model that spec 04’s geom_smooth(method = "lm") fits implicitly. The one difference is that x here is episode number, where spec 04 used air date.
  • Across-season planes treat season as a cardinal number. That goes against the decision above, and it has to: a plane needs a continuous y. Season becomes a quantity, and the model assumes each season shifts the rating by the same amount as the one before.
    • The flat plane adds episode and season effects.
    • The twisted plane adds their interaction, so the within-season slope changes steadily from season to season.

Comparing the fits shows the cost of that assumption. The plane explains 0.18 of the variance in ratings, and the twisted plane 0.19. The nine separate lines explain 0.46, but they use 18 parameters to do it.

The within-season model is written without an overall intercept (0 + ...), so its coefficients are each season’s own intercept and slope, which is what the table shows. Without an intercept, R’s summary() measures R² against zero rather than against the mean rating, which inflates it. So the R² quoted above comes from the same model refitted with an intercept, which has the same fitted lines and the same residuals.

From a lead to an ensemble (autonomous)

ImportantProduced autonomously by Claude Opus 5.5

For this section the facilitator asked only for “something with the transcripts”. The agent chose the question, the measures, the figures and every design decision in them, so none of them was decided by the facilitator or the session group. This is the contrast case described on the home page. Its fuller form, where an agent picks the dataset as well, is the claude-fable-vision-ds-test experiment (repository).

  arrange(season, episode) |>
  mutate(ep_seq = row_number())

shares <- lines_clean |>
  count(season, episode, character) |>
  group_by(season, episode) |>
  mutate(share = n / sum(n)) |>
  ungroup()

leads <- c("Michael", "Dwight", "Jim", "Pam", "Andy")
lead_shares <- shares |>
  mutate(who = if_else(character %in% leads, character, "everyone else")) |>
  group_by(season, episode, who) |>
  summarise(share = sum(share), .groups = "drop") |>
  complete(nesting(season, episode), who, fill = list(share = 0)) |>
  left_join(episodes, by = c("season", "episode")) |>
  mutate(who = factor(who, levels = c(leads, "everyone else")))

# Effective number of speakers: the inverse Simpson index of line shares.
# One speaker with every line scores 1; ten speakers with equal shares score 10.
breadth <- shares |>
  group_by(season, episode) |>
  summarise(eff_speakers = 1 / sum(share^2), .groups = "drop") |>
  left_join(episodes, by = c("season", "episode"))

eff_by_season <- breadth |> group_by(season) |> summarise(eff = mean(eff_speakers))
michael_by_season <- lead_shares |> filter(who == "Michael") |>
  group_by(season) |> summarise(share = mean(share))

pooled   <- lm(imdb_rating ~ eff_speakers, data = breadth)
within   <- lm(imdb_rating ~ eff_speakers + factor(season), data = breadth)
pooled_r <- cor(breadth$eff_speakers, breadth$imdb_rating)
season_starts <- episodes |> group_by(season) |> summarise(start = min(ep_seq))

The question the agent chose. The Office started as a show about one man and became an ensemble. Can the transcripts measure that shift? And does a broader ensemble go with better or worse ratings?

In season 1, Michael speaks 33% of all lines in an average episode. By season 7, his last as a regular, that has fallen to 20%. The effective number of speakers is the number of equally talkative characters that would give an episode’s spread of lines. It rises from 5.2 in season 1 to 10.6 in season 9.

The grammar point. The same move as spec 04 against spec 05 changes the answer: one smoother, or one per group, chosen by where a single mapping sits. With group-level confounding, the choice of layer decides whether the figure supports the claim.

What the data can’t say

IMDb ratings come from self-selected raters voting years after broadcast, so they measure how the show is remembered by people who chose to rate it. They don’t measure how it was received at the time.

The episode counts differ between tables (188 rated episodes against 186 in the transcripts). The sources likely split two-part episodes differently. Check any join for dropped rows.

The transcripts are fan-made, so character labels are inconsistent. The effective-speaker measure counts lines, not words or screen time, so a character with many one-word lines counts as much as one with a few speeches.

The 3D planes assume season acts as a number, which the group rejected for the 2D figures. They are shown to make that assumption, and its cost, visible.

## A 3D view, with the models made explicit

```{r models}
# Within-season lines: season as a category, with its own intercept and slope.
# This parameterisation gives each season's intercept and slope directly.
m_lines <- lm(imdb_rating ~ 0 + factor(season) + factor(season):episode, data = ratings)

# Across-season planes: season as a cardinal number.
m_plane <- lm(imdb_rating ~ episode + season, data = ratings)   # flat plane
m_twist <- lm(imdb_rating ~ episode * season, data = ratings)   # twisted plane

r2 <- \(m) sprintf("%.2f", summary(m)$r.squared)

# Comparable R² for the within-season model: refit it with an intercept (same fitted
# values, same residuals) so R² is measured against the mean rating, not against zero.
r2_lines <- summary(lm(imdb_rating ~ factor(season) * episode, data = ratings))$r.squared
```

Rating is elevation, episode is x and season is y. Use the buttons to add one of three linear models. The table alongside updates to show the model behind the surface, its `lm()` call, and its coefficients. Drag to rotate the view, and scroll to zoom.

Seen from straight above, this is the heatmap again, with rating as height instead of colour.

The buttons offer two kinds of model:

- **Within-season lines** treat season as a category, as the facilitator decided. Each season gets its own intercept and slope, so this is the model that spec 04's `geom_smooth(method = "lm")` fits implicitly. The one difference is that x here is episode number, where spec 04 used air date.
- **Across-season planes** treat season as a **cardinal** number. That goes against the decision above, and it has to: a plane needs a continuous y. Season becomes a quantity, and the model assumes each season shifts the rating by the same amount as the one before.
  - The flat plane adds episode and season effects.
  - The twisted plane adds their interaction, so the within-season slope changes steadily from season to season.

Comparing the fits shows the cost of that assumption. The plane explains `r r2(m_plane)` of the variance in ratings, and the twisted plane `r r2(m_twist)`. The nine separate lines explain `r sprintf("%.2f", r2_lines)`, but they use `r length(coef(m_lines))` parameters to do it.

The within-season model is written without an overall intercept (`0 + ...`), so its coefficients are each season's own intercept and slope, which is what the table shows. Without an intercept, R's `summary()` measures R² against zero rather than against the mean rating, which inflates it. So the R² quoted above comes from the same model refitted with an intercept, which has the same fitted lines and the same residuals.

```{r ensemble}
lines_clean <- lines |> mutate(character = str_squish(character))
episodes <- lines_clean |>
  distinct(season, episode, imdb_rating) |>
  arrange(season, episode) |>
  mutate(ep_seq = row_number())

shares <- lines_clean |>
  count(season, episode, character) |>
  group_by(season, episode) |>
  mutate(share = n / sum(n)) |>
  ungroup()

leads <- c("Michael", "Dwight", "Jim", "Pam", "Andy")
lead_shares <- shares |>
  mutate(who = if_else(character %in% leads, character, "everyone else")) |>
  group_by(season, episode, who) |>
  summarise(share = sum(share), .groups = "drop") |>
  complete(nesting(season, episode), who, fill = list(share = 0)) |>
  left_join(episodes, by = c("season", "episode")) |>
  mutate(who = factor(who, levels = c(leads, "everyone else")))

# Effective number of speakers: the inverse Simpson index of line shares.
# One speaker with every line scores 1; ten speakers with equal shares score 10.
breadth <- shares |>
  group_by(season, episode) |>
  summarise(eff_speakers = 1 / sum(share^2), .groups = "drop") |>
  left_join(episodes, by = c("season", "episode"))

eff_by_season <- breadth |> group_by(season) |> summarise(eff = mean(eff_speakers))
michael_by_season <- lead_shares |> filter(who == "Michael") |>
  group_by(season) |> summarise(share = mean(share))

pooled   <- lm(imdb_rating ~ eff_speakers, data = breadth)
within   <- lm(imdb_rating ~ eff_speakers + factor(season), data = breadth)
pooled_r <- cor(breadth$eff_speakers, breadth$imdb_rating)
season_starts <- episodes |> group_by(season) |> summarise(start = min(ep_seq))
```

**The question the agent chose.** *The Office* started as a show about one man and became an ensemble. Can the transcripts measure that shift? And does a broader ensemble go with better or worse ratings?

In season 1, Michael speaks `r scales::percent(michael_by_season$share[1], 1)` of all lines in an average episode. By season 7, his last as a regular, that has fallen to `r scales::percent(michael_by_season$share[7], 1)`. The *effective number of speakers* is the number of equally talkative characters that would give an episode's spread of lines. It rises from `r sprintf("%.1f", eff_by_season$eff[1])` in season 1 to `r sprintf("%.1f", eff_by_season$eff[9])` in season 9.

**Design choices (the agent's).**

- It used a stacked area of *shares*, not counts, because episodes differ in length and the question is about balance.
- The five leads are named and everyone else is pooled in grey. The transcripts have hundreds of character labels, and colour can't carry them.
- Okabe-Ito hues keep the leads distinguishable for colour-blind readers.
- White rules mark the season boundaries, and the x-axis labels sit at season starts instead of at arbitrary episode numbers.

Pooled across the whole run, the effective number of speakers and the rating are negatively correlated (r = `r sprintf("%.2f", pooled_r)`). Each extra effective speaker goes with a rating `r sprintf("%.2f", abs(coef(pooled)[2]))` points lower. Give each season its own level, with `lm(imdb_rating ~ eff_speakers + factor(season))`, and the common within-season slope is `r sprintf("%+.2f", coef(within)[2])` per extra speaker (p = `r sprintf("%.2f", summary(within)$coefficients[2, 4])`), which is indistinguishable from zero. The nine season lines in the figure scatter both ways around it, with no consistent direction.

The pooled slope comes from *between*-season differences. The later seasons both spread their lines more widely and are rated lower. Nothing in the data shows that one causes the other. Michael's departure after season 7, cast and writing-staff changes, and the age of the show all shift ratings and ensemble breadth together.

**The grammar point.** The same move as spec 04 against spec 05 changes the answer: one smoother, or one per group, chosen by where a single mapping sits. With group-level confounding, the choice of layer decides whether the figure supports the claim.

## Where this fits

The workshop's central argument is that agents collapse the *implementation* part of analysis, which leaves the analyst more time for the design decisions. Knowledge Tree and Butterfly, the facilitator's company, is building this into its offering [**Science Supercharged**](https://ktandb.co.uk/ways-to-work#science-supercharged). It brings the habits software teams use to keep their work alive to research analysis: version control, specification before analysis, and checks before publication. The spec-first loop in these sessions is a small, visual instance of that. The decisions go into a file that can be reviewed, an agent does the typing, and the record of what was decided survives the session.

[*The knowledge tree*](https://ktandb.co.uk/knowledge-tree) explains the wider idea: keep alive the structure that produces an analysis, not just the outputs. The 75-second film [*A Hand of Tasks*](https://ktandb.co.uk/hand-of-tasks) frames the shift in four task types: specify, implement, review and feedback. Sessions like this one practise moving time out of *implement* and into the other three.

**How much time is at stake? Illustrative orders of magnitude, not measurements.** These estimates are deliberately low.

| Piece of work | By hand, experienced R user | Agent-assisted (human time) |
|---|---|---|
| One spec revision to a polished, labelled figure | 10–30 minutes | about 1 minute |
| This page's figures, including the 3D model view and its linked table | 1–2 days | 1–2 hours |
| Rebuilding a published paper's analysis on new data (Science Supercharged case study) | weeks | 2–3 days |

The saving is roughly an order of magnitude on implementation. Specifying, reviewing and deciding take as long as before, which is the point.

## What the data can't say

IMDb ratings come from self-selected raters voting years after broadcast, so they measure how the show is remembered by people who chose to rate it. They don't measure how it was received at the time.

The episode counts differ between tables (`r nrow(ratings)` rated episodes against `r n_ep_lines` in the transcripts). The sources likely split two-part episodes differently. Check any join for dropped rows.

The transcripts are fan-made, so character labels are inconsistent. The effective-speaker measure counts lines, not words or screen time, so a character with many one-word lines counts as much as one with a few speeches.

The 3D planes assume season acts as a number, which the group rejected for the 2D figures. They are shown to make that assumption, and its cost, visible.
